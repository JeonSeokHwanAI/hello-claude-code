AI 오케스트레이터 패턴 6가지

AI를 어떻게 일시키면 더 정확하고 실용적으로 움직이는가 — LLM을 단계적으로 문제 해결하고 도구를 쓰고 결과를 개선하게 만드는 6가지 운영 패턴을 비개발자 관점에서 정리했습니다.

먼저 이해하면 좋은 핵심 개념

🧠

LLM

사람의 말을 이해하고 문장을 생성하는 AI 모델. ChatGPT·Claude·Gemini.

🤖

에이전트(Agent)

답변만 하지 않고 목표를 받아 중간 판단과 도구 사용까지 수행하는 AI.

🎯

오케스트레이터

여러 단계의 판단·도구 호출·검토·협업 흐름을 조율하는 "팀장" 역할.

그냥 "잘해봐"라고 시키면 결과가 들쭉날쭉합니다. 패턴을 적용하면 AI의 행동 방식이 구조화되어 정확도와 재현성이 높아집니다.

6가지 패턴

PATTERN 1

ReAct (Reason + Act)

모델이 추론하고(Reason), 행동하고(Act), 결과를 관찰(Observation)하며 문제를 해결하는 가장 기초적인 패턴. "생각하고, 해보고, 결과를 보고, 다시 생각하는 방식".

예시 — "내일 서울 날씨 알려줘": 생각(내 지식만으론 불확실) → 행동(날씨 API/검색 호출) → 관찰(결과 확인) → 답변. 환각(hallucination)을 줄이고 도구 사용과 잘 결합됩니다.

언제: 한 번에 풀기 어렵거나, 중간 단계 확인이 중요하거나, 검색·계산·조회가 필요할 때.

PATTERN 2

CodeAct

자연어 설명만 하지 않고 직접 코드를 생성·실행하여 문제를 해결. "손으로 계산하는 대신 계산기를 꺼내 쓰는 방식".

예시: CSV에서 매출 상위 10개 뽑기 · PDF 여러 개에서 특정 문구 페이지 찾기 · 로그 집계로 에러 빈도 계산. 말로 추론하는 것보다 실행 결과가 더 정확합니다.

언제: 수치 계산·파일 처리·반복 검증이 중요할 때. 주의: 실행 환경 필요, 잘못된 코드 검증 필수.

PATTERN 3

Tool Use (Function Calling)

모델이 외부 API·DB·웹 검색·사내 시스템 같은 도구를 호출하게 연결. "AI에게 손과 발을 붙여주는 것".

예시: 구글 캘린더 일정 조회 · 웹 검색으로 최신 뉴스 · CRM 고객 조회 · 텔레그램 요약 전송.

핵심: 많은 에이전트 시스템은 사실상 ReAct + Tool Use 조합으로 시작합니다.

PATTERN 4

Self-Reflection (자기 성찰)

자신이 만든 결과물을 스스로 검토·수정한 뒤 최종안을 내놓는 방식. "초안을 쓴 뒤 스스로 검토자 역할도 한 번 더".

예시: 보고서 초안 후 "논리 점검·중복 제거·누락 확인" · 이메일 후 "오해 표현 검토" · 코드 후 "버그·예외 케이스 점검".

언제: 완성도가 중요할 때. 주의: AI가 자기 답을 완벽히 비판하진 못함 → 중요 업무는 사람 검토 병행.

PATTERN 5

Multi-Agent Flow

하나의 모델이 다 하지 않고 역할이 다른 여러 에이전트가 협력. "AI 한 명보다 팀을 꾸리는 방식". 기획·조사·작성·리뷰 에이전트로 분업.

예시 — 강의 자료 만들기: 조사(사례·통계) → 요약(핵심 압축) → 슬라이드(구조화) → 리뷰(초보자 관점 검토).

언제: 규모가 크고 단계가 많거나, 서로 다른 전문성·독립 검토가 필요할 때. 주의: 작은 작업엔 과한 구조.

PATTERN 6

Agentic RAG

기존 RAG(문서 검색→답변)에서 한 발 더 — 어떤 문서가 필요한지 스스로 판단하고, 부족하면 다시 찾거나 검색 전략을 바꾸는 능동형. "도서관 사서처럼 자료를 다시 찾아보는 방식".

예시: 사내 휴가 규정 찾기 · 과거 의사결정 근거 추적 · 매뉴얼+FAQ 종합 답변.

주의: 검색 품질·문서 정리·메타데이터에 좌우됨. 저장 체계가 엉망이면 성능 저하.

한눈에 비교

패턴한 줄 요약초보자 비유대표 용도
ReAct생각하고 행동하며 반복 해결문제 풀면서 중간 점검검색형 문제 해결
CodeAct코드를 실행해 해결계산기 대신 직접 프로그램데이터 분석·파일 처리
Tool Use외부 도구 연결AI에 손과 발 붙이기API 호출·시스템 연동
Self-Reflection스스로 검토 후 개선초안 쓰고 다시 검토보고서·이메일·코드 점검
Multi-Agent여러 AI가 역할 분담팀을 꾸려 일하기복잡한 프로젝트
Agentic RAG능동적으로 문서 재검색사서가 자료를 다시 찾기사내 문서·지식 응답

실무에서 자주 쓰는 패턴 조합

현업에선 한 패턴 단독보다 여러 패턴을 조합해 업무 흐름을 만듭니다.

조합 ① · 문서·규정 검색

Agentic RAG + Self-Reflection

  • 질문을 분석해 어떤 문서를 함께 봐야 하는지 스스로 판단
  • 답하기 전 점검: 최신 버전인가 · 예외 조항 누락 없나 · 근거 문서가 여럿일 가능성
  • "자료를 똑똑하게 찾고, 답하기 전 다시 검토" — 규정 확인·감사 대응·내부 Q&A
조합 ② · 실시간 리서치

Tool Use + ReAct

  • 웹 검색·API·데이터 조회 도구를 호출하며 단계적으로 진행
  • 가격 확인 → 리뷰 수집 → 중복 제거 → 핵심 요약
  • Tool Use가 손과 발, ReAct가 순서를 정하는 머리 — 시장조사·벤치마킹·뉴스 모니터링
조합 ③ · 기획·콘텐츠

Multi-Agent Flow

  • 전략가(타깃·소구점) → 카피라이터(문구 초안) → 비평가(톤·설득력 피드백)
  • 혼자보다 다양한 관점 + 초안 완성도·수정 속도 동시 향상
  • "작은 팀을 꾸려 일시키기" — 캠페인 기획·콘텐츠·보고서 초안

학습 순서 · 정리

6가지를 한꺼번에 구현하려 하지 말고, 아래 순서로.

1. ReAct          단계적 사고·행동의 기본 구조
2. Tool Use       외부 정보·액션 수행
3. Self-Reflection 결과물 재검토로 품질 향상
4. CodeAct        계산·분석·파일 작업으로 확장
5. Agentic RAG    문서 검색·지식 응답 강화
6. Multi-Agent    규모가 커지면 팀 구조로
실무에서는 ReAct + Tool Use + Self-Reflection 조합만으로도 상당히 강력한 자동화를 만들 수 있습니다.

한 문장 요약 — "AI를 잘 쓰는 핵심은, 생각하게 하고, 도구를 쓰게 하고, 다시 검토하게 만드는 것이다."

사무직 실무라면 이 세 조합부터:

  • 규정·매뉴얼·보고서 검색 → Agentic RAG + Self-Reflection
  • 시장조사·경쟁사·실시간 정보 → Tool Use + ReAct
  • 기획·초안·피드백 반복 → Multi-Agent Flow
