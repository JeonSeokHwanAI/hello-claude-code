## 0. 대전제 — 월간클로드는 연속 프로그램이다

**이 강의는 4주 완결 상품이 아니다.** 매월 이어지는 프로그램의 한 구간이다.

이 전제가 설계 전체를 바꾼다.

| 4주 완결로 볼 때 | 연속 프로그램으로 볼 때 |
|---|---|
| 4주 안에 정식 출시까지 못 하면 실패 | 4주엔 **올리는 데까지**, 정식 출시는 다음 달에 이어감 |
| 못 끝낸 사람 = 낙오 | 못 끝낸 사람 = **다음 기수 참여 동기** |
| 기수 간 단절 | 기수가 쌓이면서 **커뮤니티 자산**이 된다 |

### 0.1 연속성이 만드는 결정적 이점 ⭐

Google Play는 신규 개인 개발자 계정에 **"테스터 12명이 14일 연속 참여한 비공개 테스트"**를 정식 출시 조건으로 요구한다. 개인이 혼자 12명을 모으는 건 현실적으로 매우 어렵고, 이것 때문에 출시를 포기하는 사람이 많다.

**그런데 우리는 매달 12명 이상이 모이는 커뮤니티다.**

```
수강생 12명 이상  →  서로의 앱에 테스터로 등록  →  14일 대기  →  전원 정식 출시 가능
```

혼자서는 못 넘는 벽을 **기수 자체가 넘겨준다.** 이건 다른 어떤 강의도 흉내내기 어려운 구조적 강점이고, 모집 문구의 핵심으로 써야 한다.

> "혼자였으면 테스터 12명 못 모아서 여기서 멈췄을 겁니다. 우리는 같이 넘습니다."

## 2. 이 강의가 실제로 파는 것

가장 중요한 인식. **결과물은 상품이 아니다.**

Claude Code에게 "내 공방 소개 페이지 만들어줘"라고 하면 20분이면 나온다. 결과물을 상품으로 내세우면 수강생은 "나 혼자 Claude한테 시켜도 되는 거 아냐?"라고 생각하게 되고, **그 생각이 맞다.**

그래서 이 강의가 파는 건 두 가지뿐이다.

### ① Claude Code를 원하는 대로 부리는 역량
한 번에 나오는 결과물이 아니라 — 마음에 안 들 때 고치는 법, 망쳤을 때 되돌리는 법, 내 취향을 기억시키는 법, 막혔을 때 뚫는 법. 혼자 하면 며칠 헤매는 구간이다.

### ② Claude가 대신 못 해주는 구간 ⭐ (이쪽이 훨씬 크다)
Claude는 코드를 써주지만 **이건 못 한다.**

- 구글 개발자 계정 만들고 $25 결제하고 신원 확인 통과하기
- 앱 서명 키 만들고 잃어버리지 않게 관리하기
- 스토어 등록정보 · 콘텐츠 등급 설문 · 데이터 보안 양식 채우기
- 개인정보처리방침 URL 준비하기
- 심사에서 반려됐을 때 원인 찾아 대응하기
- 내부 테스트 → 비공개 테스트 → 프로덕션 트랙 승격 절차 밟기

**3주차가 이 강의의 진짜 상품이다. 나머지 3주는 3주차로 가기 위한 재료다.**

## 3. 대상 & 전제

### 3.1 수강 대상
- **신규 입문자 위주.** Claude Code를 안 써봤거나 몇 번 만져본 수준.
- **자영업자 비중 높음** — 이게 전략적으로 중요하다 (§3.2)
- 비개발자 전제. HTML/CSS/JS를 모른다고 가정한다.

### 3.2 자영업자 타깃이 전략적으로 유리한 이유 ⭐
Google Play의 12명/14일 테스터 요건은 **개인 개발자 계정에만 적용**된다. **사업자(조직) 계정은 면제**다.

즉 **사업자등록증이 있는 자영업자는 이 벽 자체를 건너뛴다.** 그대로 모집 문구가 된다.

> "사업자등록번호 있으시죠? 그럼 남들 2주 걸리는 구간을 건너뜁니다."

### 3.3 수강생이 부담하는 실비 (모집 단계에서 반드시 명시)
| 항목 | 금액 | 비고 |
|---|---|---|
| Claude Pro 구독 | 월 $20~ | 필수. 무료 플랜은 실습 중 한도에 막힘 |
| Google Play 개발자 등록 | **$25 (1회)** | 필수. 평생 1회 |
| Vercel · GitHub · 공공데이터포털 · Expo | 무료 | — |

> 이걸 숨기면 2주차에 반드시 항의가 들어온다. 랜딩페이지 3곳(준비물·수강료·FAQ)에 적는다.

### 3.4 명시적 비대상
- 현업 개발자가 프로덕션 아키텍처를 배우러 오는 강의가 아니다.
- iOS 앱은 다루지 않는다. (Apple 개발자 프로그램은 연 $99 + 심사가 훨씬 까다로움)
- 회사 보안정책상 개인 PC 설치가 불가한 분

## 5. 커리큘럼 구조

### 5.1 주차별 독립 주제
4주를 하나의 프로젝트로 잇지 않는다. **각 주차가 독립된 주제**다. 다만 3주차는 1·2주차 결과물을 배포 대상으로 쓴다.

```
Week 1              Week 2              Week 3                    Week 4
웹사이트 만들기      앱 만들기      ┌→ Vercel에 웹사이트 올리기      공공데이터
   (독립)            (독립)        └→ Play Store에 앱 올리기        (독립)
      └──────────────┴──────────────────┘
                 3주차의 배포 대상
```

### 5.2 니즈 분기 — 유형 3종
수강생 니즈가 제각각이라는 문제는 주차를 늘려서가 아니라 **매 주차 안의 유형 분기**로 푼다. 강사는 하나만 시연하고, 수강생은 자기 유형 레시피를 받는다.

| 유형 | 웹사이트 (W1) | 앱 (W2) |
|---|---|---|
| 🏪 **가게형** | 메뉴·영업시간·오시는길·예약문의 | 우리가게 앱 (메뉴·쿠폰·예약) |
| 🧑 **개인형** | 포트폴리오·이력·작업물·연락처 | 내 작업물 앱 |
| 🛠 **도구형** | 서비스 소개·기능·문의 | 기록·계산·관리 앱 |

### 5.3 결과물 축 / 역량 축

### Week 2 (9/21) — 안드로이드 앱 만들기

**목표**: 내 폰에서 실제로 실행되는 안드로이드 앱을 만든다.

**기술 경로: Expo (React Native) 권장**

| 경로 | 로컬 설치 | 빌드 | 난이도 |
|---|---|---|---|
| **Expo** ⭐ | Node.js만 | **EAS 클라우드 빌드**가 `.aab` 생성 | 🟢 |
| Flutter | Flutter SDK + Android Studio (10GB+) | 로컬 | 🔴 |
| Capacitor | Android Studio 필요 | 로컬 | 🟡 |
| PWABuilder | 없음 | URL만 넣으면 `.aab` | 🟢 (단, 웹뷰라 심사 반려 위험) |

**Expo를 고르는 이유**
1. 로컬에 Android Studio를 안 깔아도 된다 → 입문자 이탈 방지 (가장 중요)
2. 빌드가 클라우드에서 돌아 `.aab`를 내려준다 → 3주차 업로드에 그대로 쓴다
3. **폰으로 QR을 찍으면 그 자리에서 앱이 실행된다** → 2주차 성취감 확보
4. Claude Code가 JS/TS를 가장 잘 다룬다
5. 진짜 네이티브 앱이라 심사 반려 위험이 낮다

| 교시 | 내용 | 시간 |
|---|---|---|
| 1 | 앱은 웹과 뭐가 다른가 / Expo 구조 5분 개념 | 15분 |
| 2 | 프로젝트 만들고 **폰에서 QR로 실행** 🎉 | 25분 |
| 3 | 화면 만들기 — 유형별 분기 (가게앱·작업물앱·도구앱) | 40분 |
| 4 | 아이콘 · 앱 이름 · 스플래시 (스토어 등록 재료) | 20분 |
| 5 | 안 될 때 대처법 / EAS 빌드 걸어두기 | 20분 |

**완성 기준선**: 내 폰에서 앱이 실행된다. 빌드가 걸려 있다.

**🏠 과제**: 앱 다듬기 + **스토어 등록 재료 준비** (아이콘 512px · 스크린샷 2장 · 앱 설명)

### Week 3 (9/28) — 배포하기 ⭐⭐ 이 강의의 핵심

**목표**: 웹사이트는 **Vercel**에, 앱은 **Google Play**에. 각각 올린다.

| 교시 | 내용 | 시간 |
|---|---|---|
| 1 | "인터넷에 올린다"는 게 뭔가 / 터미널·Git 최소한 | 20분 |
| 2 | **[웹] GitHub → Vercel 배포** → 공개 URL 획득 | 30분 |
| 3 | **[앱] `.aab` 빌드 + Play Console 앱 등록** | 30분 |
| 4 | **[앱] 스토어 등록정보 채우기** — 설명·스크린샷·콘텐츠등급·데이터보안·**개인정보처리방침 URL** | 30분 |
| 5 | **[앱] 내부 테스트 출시 → 내 폰에 Play 스토어로 설치** 🎉 | 20분 |
| 6 | 정식 출시 로드맵 안내 (§6.3.2) | 10분 |

#### 6.3.1 개인정보처리방침 URL — 아름다운 연결
스토어 등록에는 개인정보처리방침 URL이 **필수**다. 그런데 수강생은 2교시에 이미 웹사이트를 배포했다.
→ **1주차 웹사이트에 방침 페이지를 추가하고 그 URL을 쓴다.** 1·2·3주차가 여기서 하나로 묶인다.

#### 6.3.2 어디까지 가는가 — 정직하게 구분

| 단계 | 3주차에 가능? |
|---|---|
| 개발자 계정 + $25 | ✅ (Week 0에 완료) |
| `.aab` 빌드 | ✅ EAS 클라우드 빌드 |
| Play Console 앱 등록 · 등록정보 입력 | ✅ |
| `.aab` 업로드 | ✅ |
| **내부 테스트 출시 → 내 폰에 스토어로 설치** | ✅ **3주차 목표** |
| 전 세계 검색·설치 (정식 공개) | 사업자 계정 = 즉시 / 개인 계정 = **+14일** |

**완성 기준선**: ① 공개 웹 URL ② Play 스토어를 통해 내 폰에 설치된 내 앱

> ⚠️ **모집 페이지에 "4주 안에 정식 출시"라고 쓰면 안 된다.** "올리는 데까지"가 정확한 약속이다. 정식 공개는 다음 달로 이어간다(§0).

**⚠️ 최대 리스크**: 이 날이 추석 대체공휴일일 가능성이 높은데 가장 중요한 회차다.
→ 녹화 필수 + 그 주 안에 **"배포 따라잡기" 보충 세션** 반드시 개설.

**🏠 과제**: URL 공유 + 앱 설치 인증 / **서로 테스터로 등록해 주기** (§0.1)

### Week 4 (10/5) — 공공데이터 활용하기

**목표**: 바깥 세상의 진짜 데이터를 웹·앱에 연결하고 다시 배포한다.

| 교시 | 내용 | 시간 |
|---|---|---|
| 1 | API란? / 키가 왜 필요한가 | 20분 |
| 2 | 공공데이터포털 — 데이터 찾고 키 받고 응답 확인 | 25분 |
| 3 | 내 웹 또는 앱에 붙이기 | 40분 |
| 4 | 비밀키 관리 (환경변수) + 재배포 | 20분 |
| 5 | **정식 출시 로드맵 + 다음 기수 안내** | 15분 |

**추천 데이터셋** (키 즉시 발급 · JSON · 응답 단순)
| 데이터 | 출처 | 왜 좋은가 |
|---|---|---|
| 🥇 박스오피스 순위 | KOBIS | 키 즉시, JSON 깔끔, 결과가 재밌음 |
| 🥇 미세먼지·대기질 | 에어코리아 | 체감도 최고 |
| 🥈 기상청 단기예보 | data.go.kr | 응답 구조가 복잡 → 강사 데모용 |
| 🥈 전국 문화축제/공연 | data.go.kr | 가게형·개인형과 궁합 좋음 |
| 🥈 서울 따릉이·지하철 | 서울 열린데이터광장 | 키 즉시 |

**⚠️ 리스크**: 일부 API는 승인에 1~2일 걸린다.
→ ① Week 0 회원가입 ② **3주차 종료 시 "쓸 데이터 정하고 키 신청"을 필수 과제로** ③ 강사 백업 키 + 샘플 JSON 준비

**🏠 과제 (졸업)**: 완성 URL·앱 제출 + 3줄 회고
