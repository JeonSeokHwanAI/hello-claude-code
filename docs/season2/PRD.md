## 0. 대전제 — 월간클로드는 "한 번 사고 계속 받는" 프로그램이다

**이 강의는 4주 완결 상품이 아니다.** 그렇다고 매달 새로 결제하는 구독도 아니다.

```
정규 4주 과정          →   수료   →   월간클로드
(유료 · 평생 1회)                    (무료 · 매달, 계속)
```

정규 4주를 한 번 수료하면, **그 뒤로 매달 열리는 월간클로드 세션에 무료로 참여할 자격**이 생긴다. 월간 세션에서는 그달에 새로 나온 주제·기술·트렌드를 다룬다.

> ⚠️ **재수강 개념이 아니다.** 정규 과정을 다시 듣는 게 아니라, 새로운 내용을 계속 받는 구조다.
> (v0.2에서 이 부분을 "다음 기수에서 이어감"으로 잘못 기술했음 — 정정)

### 0.1 이 구조를 택한 이유
AI는 반년이면 판이 바뀐다. 오늘 배운 방식이 몇 달 뒤엔 낡은 방식이 된다. 한 번 배우고 끝나는 강의로는 따라갈 수 없다.
→ **정규 4주는 입장권**, 그 뒤로는 새로 나온 것을 계속 전달한다.

### 0.2 이 구조가 만드는 결정적 이점 ⭐

Google Play는 신규 개인 개발자 계정에 **"테스터 12명이 14일 연속 참여한 비공개 테스트"**를 정식 출시 조건으로 건다. 혼자 12명을 모으는 게 어려워 여기서 포기하는 사람이 많다.

**그런데 월간클로드는 매달 사람이 모이는 커뮤니티다.**

```
수강생 12명 이상  →  서로의 앱에 테스터로 등록  →  14일  →  전원 정식 출시 가능
```

혼자서는 못 넘는 벽을 **기수가 넘겨준다.** 게다가 수료생이 계속 남아 있으므로 **테스터 풀이 유지된다.** 다른 강의가 흉내내기 어려운 구조적 강점이며, 모집 페이지의 핵심 메시지로 쓰고 있다.

## 2. 이 강의가 실제로 파는 것

**결과물은 상품이 아니다.** Claude에게 "내 공방 소개 페이지 만들어줘"라고 하면 20분이면 나온다. 결과물을 내세우면 수강생은 "나 혼자 시켜도 되는 거 아냐?"라고 생각하게 되고, 그 생각이 맞다.

그래서 파는 건 두 가지뿐이다.

### ① Claude Code를 원하는 대로 부리는 역량
한 번에 나오는 결과물이 아니라 — 마음에 안 들 때 고치는 법, 망쳤을 때 되돌리는 법, 내 취향을 기억시키는 법.

### ② Claude가 대신 못 해주는 구간 ⭐ (이쪽이 훨씬 크다)

| 🌐 웹사이트 쪽 | 📱 앱 쪽 |
|---|---|
| GitHub에 올리고 Vercel에 연결 | 구글 개발자 계정 · 신원 확인 |
| 내 주소 정하기 | 앱 서명 키 만들고 관리 |
| 카톡 공유 미리보기(OG) | 스토어 등록정보 · 콘텐츠 등급 · 데이터 보안 양식 |
| 검색 노출 · 개인정보처리방침 페이지 | 심사 반려 대응 |
| | 테스트 트랙 → 정식 출시 승격 |

**3주차가 이 강의의 본체다. 나머지 3주는 3주차에 올릴 물건을 만드는 시간이다.**

> ⚠️ **랜딩페이지 작성 시 주의**: 내용이 앱 쪽으로 쏠리기 쉽다. v0.2 페이지에서 웹:앱 언급 비율이 21:74였음. 웹사이트 파트를 의식적으로 균형 잡아야 한다.

## 5. 커리큘럼 구조

### 5.1 주차별 독립 주제
4주를 하나의 프로젝트로 잇지 않는다. 각 주차가 독립 주제이며, 3주차만 1·2주차 결과물을 배포 대상으로 쓴다.

```
Week 1          Week 2         Week 3                      Week 4
웹사이트         앱          ┌→ Vercel에 웹사이트          공공데이터
 (독립)        (독립)        └→ Play Store에 앱             (독립)
    └─────────────┴──────────────┘
              3주차의 배포 대상
```

### 5.2 니즈 분기 — 유형 3종
주차를 늘리는 대신 **주차 안에서 갈라진다.** 강사는 하나만 시연하고, 수강생은 자기 유형 레시피를 받는다.

| 유형 | 웹 (W1) | 앱 (W2) |
|---|---|---|
| 🏪 가게형 | 메뉴·영업시간·오시는길·예약문의 | 우리가게 앱 |
| 🧑 개인형 | 포트폴리오·이력·작업물·연락처 | 내 작업물 앱 |
| 🛠 도구형 | 서비스 소개·기능·문의 | 기록·계산·관리 앱 |

### Week 2 (9/21) — 안드로이드 앱 만들기

**목표**: 내 폰에서 실제로 실행되는 안드로이드 앱을 만든다.

**기술 경로: Expo (React Native) 권장** — *강사 리허설 후 최종 확정 필요*

| 경로 | 로컬 설치 | 빌드 | 난이도 |
|---|---|---|---|
| **Expo** ⭐ | Node.js만 | **EAS 클라우드 빌드**가 `.aab` 생성 | 🟢 |
| Flutter | Flutter SDK + Android Studio (10GB+) | 로컬 | 🔴 |
| Capacitor | Android Studio 필요 | 로컬 | 🟡 |
| PWABuilder | 없음 | URL만 넣으면 `.aab` | 🟢 (웹뷰라 심사 반려 위험) |

**Expo를 고르는 이유**
1. Android Studio를 안 깔아도 된다 → **입문자 이탈 방지 (가장 중요)**
2. 클라우드 빌드가 `.aab`를 내려준다 → 3주차 업로드에 그대로 사용
3. **폰으로 QR을 찍으면 그 자리에서 실행** → 2주차 성취감 확보
4. Claude Code가 JS/TS를 가장 잘 다룬다
5. 진짜 네이티브 앱이라 심사 반려 위험이 낮다

**완성 기준선**: 내 폰에서 앱이 실행된다. 빌드가 걸려 있다.
**과제**: 스토어 등록 재료 준비 (아이콘 512px · 스크린샷 2장 · 앱 설명)

#### 6.3.1 개인정보처리방침 URL — 웹과 앱이 만나는 지점
스토어 등록에 개인정보처리방침 URL이 **필수**인데, 수강생은 2교시에 이미 웹사이트를 배포했다.
→ **1주차 웹사이트에 방침 페이지를 추가하고 그 URL을 쓴다.** 1·2·3주차가 여기서 하나로 묶인다.

#### 6.3.2 어디까지 가는가 — 정직하게 구분

| 단계 | 4주 안에? |
|---|---|
| 🌐 여러 섹션 갖춘 사이트 만들기 | ✅ 1주차 |
| 🌐 **인터넷에 올려서 주소 갖기 (아무나 접속)** | ✅ **3주차 · 조건 없음** |
| 🌐 카톡 공유 미리보기 · 검색 노출 | ✅ 3주차 |
| 📱 앱 파일 빌드 · Play Console 등록 · 업로드 | ✅ 3주차 |
| 📱 **플레이스토어로 내 폰에 설치** | ✅ **3주차 목표** |
| 📱 아무나 검색해서 받기 (정식 공개) | 사업자 계정 = 즉시 / 개인 = **+14일** |

> ⚠️ **"4주 안에 정식 출시"라고 쓰면 안 된다.** "올리는 데까지"가 정확한 약속이다.
> 웹사이트는 조건이 없다는 점을 강조하면 균형이 맞는다.

## 7. 구축 완료된 운영 시스템

### 7.1 모집 사이트
| | |
|---|---|
| 주소 | **https://monthly-claude-2.vercel.app** (신청: `/apply`) |
| Vercel 프로젝트 | `monthly-claude-2` — **1기(`hello-claude-code`)와 완전 분리** |
| 소스 | `season2-site/` (저장소 루트가 아님 — Vercel `rootDirectory` 설정됨) |

> ⚠️ **주의**: Vercel 프로젝트가 GitHub 저장소에 연결돼 있고 `rootDirectory=season2-site`로 지정돼 있다. 이 설정이 비면 푸시할 때 저장소 루트(1기)가 배포되어 2기 주소에 1기 페이지가 뜬다. (실제 발생했던 사고)

### 7.2 신청 접수
- **Supabase** `season2_applications` 테이블
- **RLS**: 익명 INSERT만 허용, SELECT 차단 → 공개 키로 명단 조회 불가
- 명단 확인은 **Supabase 대시보드 → Table Editor**에서만

### 7.3 신청 완료 메일 자동 발송
```
신청 → Supabase INSERT → Database Webhook → Apps Script → 메일 2통
```
| 받는 사람 | 내용 |
|---|---|
| **신청자** | 접수 확인 + 결제 안내 (**블크업 13기 여부로 금액 자동 분기**) + 카톡방 링크 + 개발자 계정 미리 신청 안내 |
| **강사** | 신청 알림 + 챙길 것 요약 + **입금 확인 후 보낼 카톡방 안내 문구** (복사용) |

- 코드: [`apps-script-mailer.template.gs`](./apps-script-mailer.template.gs) (실제 값 버전은 로컬 전용, gitignore)
- 설치: [`email-setup-guide.md`](./email-setup-guide.md)

### 7.4 카톡 오픈채팅방
- 링크: 메일러 CONFIG `KAKAO_URL` 참고 (공개 저장소라 미기재)
- **참여 코드로 게이팅** — 신청 메일엔 링크만, **코드는 입금 확인 후 개별 전달**
  (신청은 무료라 코드가 없으면 미결제자가 들어온다)

### 7.5 신청 폼 — 의도적으로 간소화
아직 신청할지 고민 중인 사람에게 20개를 물으면 그냥 닫는다. **10개로 축소.**

| 받는 것 | 안 받는 것 (→ 개강 전 사전 설문) |
|---|---|
| 이름(카톡 닉네임) · 이메일 · 연락처 | 만들고 싶은 것 · 유형 |
| **블크업 13기 여부** (금액이 갈리므로 필수) | 경험 수준 · 배포 경험 |
| 유입경로(선택) | 사업자등록증 · 개발자 계정 진행상황 |
| OS · 개인/회사 PC · 폰 · Claude 구독 | 월요일 참석 가능 여부 · 연휴 참석 |
| 궁금한 점(선택) · 개인정보 동의 | 후기 공유 의향 |
