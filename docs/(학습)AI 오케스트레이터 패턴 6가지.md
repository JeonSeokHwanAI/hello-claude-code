# AI 오케스트레이터 패턴 6가지

AI 오케스트레이터 패턴은 거대언어모델(LLM)이 단순히 "문장을 잘 만드는 도구"를 넘어, 문제를 단계적으로 해결하고 외부 도구를 활용하며 결과를 개선하도록 설계하는 방식입니다.

쉽게 말하면, **AI를 어떻게 일시키면 더 정확하고 실용적으로 움직이는가**에 대한 운영 패턴이라고 볼 수 있습니다.

---

## 먼저 이해하면 좋은 핵심 개념

### LLM이란?
- 사람의 말을 이해하고 문장을 생성하는 AI 모델입니다.
- 예: ChatGPT, Claude, Gemini 같은 대화형 AI

### 에이전트(Agent)란?
- 단순 답변만 하는 것이 아니라, 목표를 받고 중간 판단과 도구 사용까지 수행하는 AI입니다.
- 예: "웹 검색해서 최신 정보를 찾고, 표로 정리해서 보고해 줘" 같은 일을 수행하는 형태

### 오케스트레이터(Orchestrator)란?
- 여러 단계의 판단, 도구 호출, 검토, 협업 흐름을 조율하는 역할입니다.
- 사람 팀에서 보면 "일의 순서를 짜고 역할을 분배하는 팀장"에 가깝습니다.

### 왜 패턴이 중요한가?
- 그냥 "잘해봐"라고 시키면 결과가 들쭉날쭉합니다.
- 패턴을 적용하면 AI의 행동 방식이 구조화되어 정확도와 재현성이 높아집니다.

---

## 1. ReAct (Reason + Act)

### 개념
가장 기초적이고 널리 쓰이는 패턴입니다. 모델이 추론하고(Reason), 행동하고(Act), 그 결과를 관찰(Observation)하면서 문제를 해결합니다.

### 작동 흐름
1. 현재 상황을 해석한다.
2. 다음 행동을 정한다.
3. 도구를 사용하거나 답을 시도한다.
4. 결과를 보고 다시 판단한다.

### 특징
- 사고 과정을 단계적으로 분리할 수 있습니다.
- 무턱대고 답을 지어내는 환각(hallucination)을 줄이는 데 도움이 됩니다.
- 도구 사용과 잘 결합됩니다.

### 초보자용 설명
초보자는 ReAct를 **"생각하고, 해보고, 결과를 보고, 다시 생각하는 방식"**으로 이해하면 됩니다.  
사람이 어려운 문제를 풀 때도 머릿속으로만 끝내지 않고, 검색해 보고, 계산해 보고, 다시 판단하듯이 AI도 그렇게 움직이게 만드는 패턴입니다.

### 쉬운 예시
"내일 서울 날씨 알려줘"라는 요청을 받았을 때:
- 생각: 내 지식만으로는 최신 날씨를 확신할 수 없다.
- 행동: 날씨 API나 웹 검색을 호출한다.
- 관찰: 검색 결과를 확인한다.
- 답변: 최신 정보를 바탕으로 사용자에게 알려준다.

### 언제 쓰면 좋은가
- 문제를 한 번에 풀기 어려울 때
- 중간 단계 확인이 중요할 때
- 검색, 계산, 조회 같은 행동이 필요한 작업일 때

---

## 2. CodeAct

### 개념
LLM이 자연어 설명만 하는 것이 아니라, **직접 코드를 생성하고 실행하여 문제를 해결하는 방식**입니다.

### 특징
- 계산, 데이터 처리, 파일 변환 같은 작업에서 강합니다.
- 말로 추론하는 것보다 실행 결과가 더 정확합니다.
- 재현 가능한 결과를 만들기 좋습니다.

### 초보자용 설명
초보자는 CodeAct를 **"AI가 직접 손으로 계산하는 대신 계산기를 꺼내 쓰는 방식"**이라고 생각하면 됩니다.  
예를 들어 숫자가 많은 엑셀 분석은 말로 대충 설명하는 것보다 Python 코드로 직접 계산하는 편이 훨씬 안전합니다.

### 쉬운 예시
- CSV 파일을 읽어서 매출 상위 10개 품목을 뽑기
- PDF 여러 개에서 특정 문구가 들어간 페이지 찾기
- 로그 파일을 집계해서 에러 빈도 계산하기

### 언제 쓰면 좋은가
- 수치 계산이 중요할 때
- 파일 처리나 데이터 변환이 필요할 때
- 결과를 반복 실행하고 검증해야 할 때

### 주의점
- 코드 실행 환경이 준비되어 있어야 합니다.
- 잘못된 코드가 실행되면 오히려 오류가 커질 수 있으므로 검증이 필요합니다.

## 3. Tool Use (Function Calling)

### 개념
모델이 외부 API, 데이터베이스, 웹 검색기, 사내 시스템 같은 **도구를 호출할 수 있게 연결하는 패턴**입니다.

### 특징
- 모델의 한계를 외부 시스템으로 보완합니다.
- 실시간 정보 접근이 가능합니다.
- 단순 답변형 AI를 "실행형 AI"로 확장할 수 있습니다.

### 초보자용 설명
초보자는 Tool Use를 **"AI에게 손과 발을 붙여주는 것"**으로 이해하면 쉽습니다.  
LLM은 기본적으로 말을 잘하는 두뇌에 가깝습니다. 그런데 실제 업무는 메일 보내기, 일정 조회, 웹 검색, 파일 저장 같은 행동이 필요합니다. Tool Use는 그 행동을 가능하게 만듭니다.

### 쉬운 예시
- 구글 캘린더에서 내일 일정 조회
- 웹 검색으로 최신 AI 뉴스 찾기
- CRM에서 고객 정보 조회
- 텔레그램으로 요약 메시지 전송

### 언제 쓰면 좋은가
- 최신 정보가 필요할 때
- 회사 내부 시스템과 연결해야 할 때
- 실제 액션까지 자동화하고 싶을 때

### 핵심 포인트
Tool Use는 매우 중요합니다. 많은 에이전트 시스템은 사실상 **ReAct + Tool Use**의 조합으로 시작합니다.

## 4. Self-Reflection (자기 성찰)

### 개념
모델이 자신이 만든 답변이나 결과물을 스스로 검토하고, 문제점을 찾고, 수정한 뒤 최종안을 내놓는 방식입니다.

### 특징
- 품질 향상에 효과적입니다.
- 실수, 누락, 모호한 표현을 줄일 수 있습니다.
- 초안 작성 후 검토 단계가 필요한 업무에 적합합니다.

### 초보자용 설명
초보자는 Self-Reflection을 **"AI가 초안을 쓴 뒤, 스스로 검토자 역할도 한 번 더 하는 것"**이라고 이해하면 됩니다.  
사람도 메일을 보낼 때 한 번 더 읽어보면 오타나 어색한 표현을 발견하듯, AI에게도 그 과정을 추가하는 것입니다.

### 쉬운 예시
- 보고서 초안 작성 후 "논리 점검, 중복 제거, 빠진 항목 확인" 요청
- 이메일 문안 작성 후 "상대방이 오해할 표현이 없는지 검토" 요청
- 코드 생성 후 "버그 가능성과 예외 케이스 점검" 요청

### 언제 쓰면 좋은가
- 정확도보다 완성도가 더 중요할 때
- 문서, 기획안, 보고서 품질을 높이고 싶을 때
- 최종 제출 전 검토 단계를 자동화하고 싶을 때

### 주의점
- AI가 자기 답을 완벽하게 비판하지는 못합니다.
- 그래서 중요한 업무는 사람 검토와 함께 쓰는 것이 안전합니다.

## 5. Multi-Agent Flow

### 개념
하나의 모델이 모든 일을 다 하는 것이 아니라, **역할이 다른 여러 에이전트가 협력하는 구조**입니다.

예를 들면 아래와 같이 역할을 나눌 수 있습니다.
- 기획 에이전트: 요구사항 정리
- 조사 에이전트: 자료 수집
- 작성 에이전트: 초안 작성
- 리뷰 에이전트: 품질 검토

### 특징
- 복잡한 작업을 분업할 수 있습니다.
- 각 역할에 맞는 전문성을 부여하기 쉽습니다.
- 대규모 워크플로우에 적합합니다.

### 초보자용 설명
초보자는 Multi-Agent Flow를 **"AI 한 명이 다 하는 것보다 팀을 꾸리는 방식"**으로 생각하면 됩니다.  
사람 조직에서도 대표가 직접 조사, 작성, 검토를 모두 하지 않듯이, AI도 역할을 나누면 더 체계적으로 움직일 수 있습니다.

### 쉬운 예시
"강의 자료 만들기" 작업을 나누면:
- 조사 에이전트: 관련 사례와 통계 수집
- 요약 에이전트: 핵심 포인트 압축
- 슬라이드 에이전트: 발표 자료 구조화
- 리뷰 에이전트: 초보자 관점에서 이해 가능한지 검토

### 언제 쓰면 좋은가
- 작업 규모가 크고 단계가 많을 때
- 서로 다른 전문성이 필요한 작업일 때
- 품질 검토를 독립적으로 두고 싶을 때

### 주의점
- 에이전트가 많아질수록 설계와 관리가 복잡해집니다.
- 작은 작업에는 오히려 과한 구조가 될 수 있습니다.

## 6. Agentic RAG (에이전틱 RAG)

### 개념
기존 RAG(Retrieval-Augmented Generation)는 문서를 검색해 답변에 반영하는 방식입니다.  
Agentic RAG는 여기서 한 단계 더 나아가, **에이전트가 어떤 문서가 필요한지 스스로 판단하고, 검색 결과가 부족하면 다시 찾거나 검색 전략을 바꾸는 능동형 방식**입니다.

### 특징
- 정적인 검색보다 유연합니다.
- 검색 실패 시 재시도 전략을 세울 수 있습니다.
- 문서가 많고 복잡한 지식베이스에서 강력합니다.

### 초보자용 설명
초보자는 Agentic RAG를 **"AI가 도서관 사서처럼 자료를 다시 찾아보는 방식"**으로 이해하면 쉽습니다.  
기존 RAG는 한 번 검색하고 끝나는 느낌이라면, Agentic RAG는 "이 자료가 부족하네, 다른 키워드로 다시 찾아보자"처럼 더 능동적으로 움직입니다.

### 쉬운 예시
- 사내 문서에서 휴가 규정 찾기
- 여러 프로젝트 문서에서 과거 의사결정 근거 추적
- 제품 매뉴얼과 FAQ를 종합해 고객 문의 답변 생성

### 언제 쓰면 좋은가
- 문서량이 많을 때
- 사내 지식 검색 품질이 중요할 때
- 한 번의 검색으로 충분하지 않은 업무일 때

### 주의점
- 검색 품질, 문서 정리 상태, 메타데이터 품질의 영향을 많이 받습니다.
- 문서 저장 체계가 엉망이면 Agentic RAG도 성능이 떨어집니다.

## 초보자를 위한 한눈에 비교

| 패턴 | 한 줄 요약 | 초보자 비유 | 대표 용도 |
|---|---|---|---|
| ReAct | 생각하고 행동하며 반복 해결 | 문제 풀면서 중간 점검 | 검색형 문제 해결 |
| CodeAct | 코드를 실행해 해결 | 계산기 대신 직접 프로그램 사용 | 데이터 분석, 파일 처리 |
| Tool Use | 외부 도구 연결 | AI에 손과 발 붙이기 | API 호출, 시스템 연동 |
| Self-Reflection | 스스로 검토 후 개선 | 초안 쓰고 다시 검토 | 보고서, 이메일, 코드 점검 |
| Multi-Agent Flow | 여러 AI가 역할 분담 | 팀을 꾸려 일하기 | 복잡한 프로젝트 |
| Agentic RAG | 능동적으로 문서 재검색 | 사서가 자료를 다시 찾기 | 사내 문서 검색, 지식 응답 |

## 실무에서 자주 쓰는 패턴 조합

현업에서는 한 가지 패턴만 단독으로 쓰는 경우보다, **여러 패턴을 조합해 업무 흐름을 만드는 경우**가 훨씬 많습니다. 아래 조합은 사무직 실무에서 특히 활용도가 높습니다.

### 1. Agentic RAG + Self-Reflection

#### 적합한 업무
- 수백 페이지의 사내 규정, 취업규칙, 급여 세칙, 보고서에서 정확한 정보 찾기

#### 어떻게 쓰이나
- AI가 질문을 분석하고, 어떤 문서를 함께 봐야 하는지 스스로 판단합니다.
- 예를 들어 "이 질문은 인사 규정뿐 아니라 급여 세칙과 예외 조항도 같이 봐야 한다"라고 판단하는 방식입니다.
- 필요한 문서를 찾은 뒤에는 바로 답하지 않고, 스스로 결과를 다시 점검합니다.

#### 자기 성찰 단계에서 확인할 것
- 내가 찾은 문서가 최신 버전인가?
- 사용자가 물어본 예외 조항을 빠뜨리지는 않았나?
- 근거가 되는 문서가 1개가 아니라 여러 개일 가능성은 없나?

#### 효과
- 단순 키워드 검색보다 훨씬 정확한 답변을 만들 수 있습니다.
- "규정집에는 없습니다"처럼 피상적인 답이 아니라, 여러 문서를 종합한 근거 중심 답변이 가능합니다.

#### 초보자용 이해 포인트
이 조합은 **"자료를 똑똑하게 찾고, 답하기 전에 다시 한 번 검토하는 방식"**입니다.  
사내 문서 검색, 규정 확인, 감사 대응, 내부 질의응답 같은 업무에 특히 잘 맞습니다.

---

### 2. Tool Use + ReAct

#### 적합한 업무
- 시장 조사
- 경쟁사 가격 추적
- 리뷰 반응 수집
- 실시간 데이터 기반 리서치

#### 어떻게 쓰이나
- AI가 웹 검색, API, 데이터 조회 도구를 호출합니다.
- 그리고 단순히 도구만 한 번 쓰고 끝나는 것이 아니라, 단계적으로 판단하며 진행합니다.
- 예를 들어 아래처럼 움직일 수 있습니다.

1. 가격 정보 확인
2. 리뷰 사이트 접속
3. 최근 반응 수집
4. 중복 제거
5. 핵심 포인트 요약

#### 효과
- 사람이 일일이 검색하고 복사해서 붙여넣던 반복 업무를 크게 줄일 수 있습니다.
- 특히 최신성이 중요한 시장조사, 벤치마킹, 뉴스 모니터링 업무에서 강합니다.

#### 초보자용 이해 포인트
이 조합은 **"도구를 꺼내 쓰면서, 다음 행동을 스스로 판단하는 방식"**입니다.  
즉, Tool Use가 손과 발이라면 ReAct는 **일의 순서를 스스로 정하는 머리**라고 보면 됩니다.

---

### 3. Multi-Agent Flow

#### 적합한 업무
- 마케팅 캠페인 기획
- 콘텐츠 제작
- 보고서 초안 작성
- 아이디어 브레인스토밍

#### 어떻게 쓰이나
하나의 AI가 모든 역할을 다 하는 대신, 서로 다른 역할의 에이전트를 팀처럼 구성합니다.

- 에이전트 A(전략가): 타깃 고객과 핵심 소구 포인트 설정
- 에이전트 B(카피라이터): 전략에 맞는 광고 문구 초안 작성
- 에이전트 C(비평가): 톤, 설득력, 타깃 적합성 피드백 제공

#### 효과
- 혼자 한 방향으로만 고민할 때보다 더 다양한 관점이 나옵니다.
- 초안의 완성도와 수정 속도를 동시에 높일 수 있습니다.

#### 초보자용 이해 포인트
이 방식은 **"AI 한 명이 아니라 작은 팀을 꾸려 일시키는 것"**입니다.  
기획, 작성, 검토를 나누면 아이디어 품질이 훨씬 안정적으로 올라갑니다.

---

## 사무직에게 특히 유용한 패턴

| 패턴 | 사무직 활용 포인트 | 비유 |
|---|---|---|
| Agentic RAG | 방대한 문서 속에서 정확한 근거 찾기 | 유능한 기록물 관리사 |
| Tool Use | 실시간 웹 검색, 일정 조회, 데이터 확인, 반복 조회 | 손 빠른 인턴 |
| Multi-Agent Flow | 기획, 보고서 작성, 아이디어 브레인스토밍 분업 | 나만의 전담 팀 |

## 초보자라면 어떤 순서로 이해하면 좋은가

처음부터 6가지를 한꺼번에 구현하려고 하면 복잡하게 느껴질 수 있습니다. 아래 순서로 이해하면 훨씬 쉽습니다.

1. **ReAct**
   - AI가 단계적으로 생각하고 행동하는 기본 구조를 익힙니다.
2. **Tool Use**
   - AI가 실제로 외부 정보를 가져오거나 액션을 수행하게 만듭니다.
3. **Self-Reflection**
   - 결과물을 한 번 더 검토하게 해서 품질을 높입니다.
4. **CodeAct**
   - 계산, 분석, 파일 작업처럼 실행이 중요한 업무에 확장합니다.
5. **Agentic RAG**
   - 문서 검색과 지식 응답을 더 똑똑하게 만듭니다.
6. **Multi-Agent Flow**
   - 작업 규모가 커졌을 때 팀 구조로 확장합니다.

실무에서는 보통 **ReAct + Tool Use + Self-Reflection** 조합만으로도 상당히 강력한 자동화를 만들 수 있습니다.

## 정리

AI 오케스트레이터 패턴은 결국 **AI를 더 잘 일하게 만드는 운영 방식**입니다.

- ReAct는 사고와 행동의 기본 틀입니다.
- CodeAct는 실행 기반 정확도를 높입니다.
- Tool Use는 외부 시스템과 연결합니다.
- Self-Reflection은 품질을 높입니다.
- Multi-Agent Flow는 복잡한 업무를 분업화합니다.
- Agentic RAG는 문서 검색을 더 능동적으로 만듭니다.

초보자 입장에서는 이 6가지를 모두 외우는 것보다, 먼저 아래 한 문장으로 기억하면 충분합니다.

> **"AI를 잘 쓰는 핵심은, 생각하게 하고, 도구를 쓰게 하고, 다시 검토하게 만드는 것이다."**

그리고 사무직 실무에서는 아래 세 가지 조합부터 적용해 보면 좋습니다.

- 규정, 매뉴얼, 보고서 검색: **Agentic RAG + Self-Reflection**
- 시장조사, 경쟁사 조사, 실시간 정보 수집: **Tool Use + ReAct**
- 기획, 초안 작성, 피드백 반복: **Multi-Agent Flow**
