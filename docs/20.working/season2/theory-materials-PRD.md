## 0. 원칙

### 0.1 커리큘럼 제목과 이론을 분리한다

1기는 커리큘럼 제목 자체가 `Skill 만들기`, `PRD 만들기`, `Agent 연동` 이었다.
**2기는 제목을 결과물 중심으로 둔다.** 수강생이 신청할 때 보는 것은 "내 웹사이트", "내 앱", "스토어 업로드"여야 한다.

| 주차 | 커리큘럼 제목 (결과물) | 참고자료로 들어가는 이론 |
|---|---|---|
| Week 1 | 내 웹사이트 만들기 | **Skill** |
| Week 2 | 안드로이드 앱 만들기 | **PRD** |
| Week 3 | 배포하기 | **GitHub · Vercel · 구글 플레이스토어** |
| Week 4 | 공공데이터 활용하기 | **공공데이터포털(data.go.kr) · API** |

> 이론은 **알면 좋은 것**이지 수업을 따라오기 위한 전제가 아니다.
> 각 페이지에 "몰라도 수업은 따라올 수 있습니다"를 명시한다.

### 0.2 분량과 톤
- 한 주차당 이론 카드 **3~5개**. 카드 하나는 3~5줄.
- 코딩을 전혀 모르는 사람이 읽는다고 가정한다. 용어를 쓰면 반드시 그 자리에서 풀어 준다.
- 1기 자료 중 그대로 유효한 것은 링크로 재사용한다 (1기 사이트 URL).

### 0.3 갱신 정책
- **Week 2(앱)** 는 도구 변화가 빨라 강사가 직접 개발하며 그때그때 채운다. 초안은 뼈대만.
- 강의 자료·영상 링크는 수업 전에 강사가 직접 채운다. 페이지에는 자리만 만들어 둔다.

## 1. Week 1 — 이론: Skill

**왜 1주차인가**: 사이트를 고치다 보면 같은 요청을 반복하게 된다. "이 작업을 매번 설명하지 않는 법"이 자연스럽게 필요해지는 시점이다.

| # | 카드 제목 | 담을 내용 |
|---|---|---|
| 1 | Claude Code는 무엇이 다른가 | 답을 말해주는 게 아니라 내 파일을 직접 고친다 · 폴더 단위로 일한다 |
| 2 | 권한 창 — 왜 자꾸 물어보는가 | 실수 방지 장치 · 자주 하는 작업만 미리 허용 · 1기 권한 가이드 링크 |
| 3 | 되돌리기 | 되돌릴 수 있다는 걸 알아야 과감하게 시킨다 |
| 4 | `CLAUDE.md` — 매번 설명하지 않는 법 | 대화 시작 시 자동으로 읽는 파일 · 취향·규칙을 적어둔다 |
| 5 | **Skill — 반복 작업을 이름 붙여 저장하기** ⭐ | 아래 상세 |

### 1.1 Skill 카드 상세

- **한 줄 정의**: 자주 시키는 작업의 순서를 글로 적어 저장해 두고, 이름으로 불러 쓰는 것.
- **왜 필요한가**: "사진 3장 받아서 크기 줄이고 사이트에 넣어줘"를 매번 설명하는 대신, 한 번 적어두고 다음부터는 이름만 부른다.
- **어디에 저장되나**: 작업 폴더의 `.claude/skills/{이름}/SKILL.md`
- **CLAUDE.md와의 차이**: `CLAUDE.md`는 **항상** 적용되는 배경 규칙, Skill은 **부를 때만** 실행되는 작업 절차.
- **실물 예시**: 이 강의 저장소에도 Skill이 들어 있다. 수강생 안내 메일을 만드는 `student-mail` Skill을 3주차에 실물로 보여준다.
- **참고**: 1기 자료 「Claude Code 공식 구조 기반 Agent-Skill 가이드」 (`docs/90.reference/`)

## 2. Week 2 — 이론: PRD

**왜 2주차인가**: 앱은 사이트보다 만들 것이 많다. 화면이 여러 개고 기능이 얽힌다.
**무엇을 만들지 먼저 글로 정리하지 않으면 Claude에게 시킬 수가 없다.** 그 글이 PRD다.

| # | 카드 제목 | 담을 내용 |
|---|---|---|
| 1 | 왜 Expo인가 | 설치 부담 없음 · 클라우드 빌드 · 진짜 네이티브 앱 |
| 2 | `.aab`가 무엇인가 | 스토어에 올리는 앱 묶음 파일 · 3주차에 그대로 사용 |
| 3 | **PRD — 만들기 전에 쓰는 글** ⭐ | 아래 상세 |
| 4 | 스토어 등록 재료 | 아이콘 512px · 스크린샷 2장 · 설명 (이번 주 과제) |
| 5 | 수업 중 계속 업데이트 | 앱 파트는 강사가 개발하며 자료를 채운다 |

### 2.1 PRD 카드 상세

- **한 줄 정의**: "무엇을, 누구를 위해, 어디까지 만들 것인가"를 미리 적어 둔 문서. Product Requirements Document.
- **왜 필요한가**: Claude는 시키는 대로 잘 만들지만, **무엇을 시킬지는 사람이 정해야 한다.** 머릿속에만 있으면 만들다 방향이 흔들린다.
- **최소 구성 4가지**
  1. 누가 쓰는가
  2. 무엇을 할 수 있어야 하는가 (화면·기능 목록)
  3. 이번에는 **하지 않을 것** ← 이게 제일 중요하다
  4. 다 됐다고 판단하는 기준
- **쓰는 법**: 직접 쓰지 않아도 된다. Claude에게 "이런 앱을 만들고 싶은데 PRD로 정리해 줘"라고 시키고 고쳐 나가는 게 빠르다.
- **실물 예시**: 이 강의 자체가 PRD로 기획됐다. `docs/20.working/season2/PRD.md`를 화면에 띄워 보여준다.
- **참고**: 1기 자료 「스킬 제작을 위한 PRD 만들기」

## 3. Week 3 — 이론: GitHub · Vercel · 구글 플레이스토어

**왜 3주차인가**: 이 회차가 강의의 본체다. 세 개의 낯선 서비스를 한 번에 만나므로, **각각이 무엇을 해주는 곳인지** 미리 알고 오면 진행 속도가 크게 달라진다.

| # | 카드 제목 | 담을 내용 |
|---|---|---|
| 1 | "인터넷에 올린다"는 게 무슨 뜻인가 | 내 컴퓨터에만 있는 파일 → 아무나 접속 가능한 주소 |
| 2 | **GitHub — 코드를 보관하는 곳** | 아래 상세 |
| 3 | **Vercel — 웹사이트를 띄워주는 곳** | 아래 상세 |
| 4 | **구글 플레이스토어 — 앱을 배포하는 곳** | 아래 상세 |
| 5 | 개인정보처리방침 URL — 웹과 앱이 만나는 지점 | 1주차 사이트에 방침 페이지를 추가하고 그 주소를 스토어에 낸다 |
| 6 | 어디까지 가는가 | 정직한 구분표 (웹은 조건 없음 / 앱은 계정 종류에 따라) |

### 3.1 GitHub

- **한 줄 정의**: 코드를 인터넷에 보관하는 창고. 그리고 **변경 이력이 남는** 창고.
- **왜 필요한가**: Vercel이 이 창고를 지켜보다가, 내용이 바뀌면 자동으로 사이트를 새로 띄운다.
- **알아둘 개념 3개**
  - **저장소(repository)** — 프로젝트 하나당 창고 하나
  - **커밋(commit)** — "여기까지 됐다"고 도장 찍기. 되돌릴 지점이 된다
  - **푸시(push)** — 내 컴퓨터의 변경분을 인터넷 창고로 올리기
- **공개 저장소 주의**: 올린 것은 누구나 본다. **비밀번호·계좌번호·API 키를 올리면 안 된다.** 실수로 올리면 지워도 이력에 남는다.
- **실물 예시**: 이 강의 저장소가 공개 저장소다. 계좌번호가 든 파일을 어떻게 제외해 두었는지 실물로 보여준다.

### 3.2 Vercel

- **한 줄 정의**: 만든 웹사이트를 **주소를 붙여 띄워주는** 서비스. 무료로 시작할 수 있다.
- **동작 방식**: GitHub 저장소를 연결해 두면 → 푸시할 때마다 → 자동으로 새 버전이 올라간다.
- **알아둘 개념 3개**
  - **배포(deploy)** — 올려서 실제로 보이게 만드는 것
  - **프로젝트 설정** — 저장소 안 어느 폴더를 사이트로 볼지 지정한다. 폴더를 옮기면 이 설정도 같이 바꿔야 한다
  - **빌드 실패** — 실패하면 **직전 성공 버전이 그대로 살아 있다.** 사이트가 죽지 않는다
- **실물 예시**: 이 강의 사이트 두 개가 각각 다른 Vercel 프로젝트로 올라가 있다. 배포 화면을 함께 본다.

### 3.3 구글 플레이스토어 (Play Console)

- **한 줄 정의**: 안드로이드 앱을 올리고 심사받고 배포하는 관리 화면.
- **개발자 계정**: 등록비 $25(1회) + 신원 확인. **보통 하루, 길면 2주.** 그래서 개강 전부터 신청하게 했다.
- **개인 계정 vs 조직 계정** ⭐
  - 개인 계정 — 정식 출시 전에 **테스터 12명이 14일 연속 참여한 비공개 테스트**를 통과해야 한다
  - 조직 계정(사업자등록증 필요) — **이 요건이 면제된다**
- **출시 단계**: 내부 테스트 → 비공개 테스트 → 공개 테스트 → 정식 출시.
  **3주차 목표는 내부 테스트까지** — 스토어를 통해 내 폰에 설치되는 것을 확인한다.
- **등록에 반드시 필요한 것**: 앱 아이콘 · 스크린샷 · 설명 · **개인정보처리방침 URL**(2교시에 배포한 사이트 주소를 쓴다)

## 4. Week 4 — 이론: 공공데이터포털 · API

**기준 사이트: https://www.data.go.kr/**

| # | 카드 제목 | 담을 내용 |
|---|---|---|
| 1 | **API가 무엇인가** | 아래 상세 |
| 2 | **공공데이터포털(data.go.kr)이란** | 아래 상세 |
| 3 | **활용신청과 인증키** | 아래 상세 |
| 4 | **추천 데이터셋** | 아래 목록 |
| 5 | **비밀키를 코드에 적으면 안 되는 이유** | 환경변수 · 공개 저장소와의 관계 |

### 4.1 API가 무엇인가

- **한 줄 정의**: 다른 곳이 가진 데이터를 **정해진 방식으로 받아오는 창구.**
- 비유: 식당 주방에 직접 들어가지 않고 **주문서를 내밀면** 음식이 나온다. 주문서 양식이 API 명세다.
- 우리가 하는 일: 주소를 하나 호출하면 → 데이터가 글자 뭉치(JSON)로 돌아온다 → 그걸 화면에 예쁘게 뿌린다.
- **JSON**: 데이터를 주고받는 표준 글자 형식. 사람도 읽을 수 있다. 읽는 법만 알면 된다.

### 4.2 공공데이터포털(data.go.kr)이란

- 정부·공공기관이 가진 데이터를 **국민 누구나 무료로** 쓸 수 있게 모아 둔 공식 창구.
- 회원가입 후 원하는 데이터를 찾아 **활용신청**하면 **인증키**를 받는다. 그 키로 데이터를 불러온다.
- 데이터 종류는 두 가지
  - **오픈 API** — 주소를 호출하면 실시간으로 최신 데이터가 온다 ← **우리가 쓸 것**
  - **파일 데이터** — 엑셀·CSV를 통째로 내려받는다. 갱신이 느리다
- 화면에서 확인할 것: 활용신청 버튼 · 승인 상태 · **일일 트래픽 한도** · 요청 변수 설명 · 미리보기

### 4.3 활용신청과 인증키

- **즉시 승인 / 심사 후 승인** 두 가지가 있다. 심사형은 **1~2일** 걸린다.
  → **3주차 종료 시점에 "쓸 데이터 정하고 키 신청"을 과제로 낸다.** 4주차 당일 신청은 늦다.
- 키는 두 형태로 준다 — **Encoding / Decoding**. 어느 것을 쓸지 헷갈려 실패하는 경우가 가장 많다.
  실패하면 다른 쪽으로 바꿔 본다.
- 승인 직후에는 **최대 1시간** 키가 동작하지 않을 수 있다.
- **일일 호출 한도**가 있다. 개발 중 반복 호출로 한도를 소진하지 않게 주의한다.
- **강사 백업 준비**: 승인이 안 난 수강생을 위해 강사 키와 샘플 JSON을 미리 준비한다.

### 4.4 추천 데이터셋

키 발급이 빠르고 응답이 단순한 것 위주로 고른다.

| 순위 | 데이터 | 왜 좋은가 |
|---|---|---|
| 🥇 | 박스오피스 (KOBIS) | 즉시 발급 · 응답 단순 · 결과가 눈에 잘 보임 |
| 🥇 | 미세먼지 (에어코리아) | 즉시 발급 · 지역별로 바로 와닿음 |
| 🥈 | 기상청 단기예보 | 친숙하지만 요청 변수가 다소 많음 |
| 🥈 | 전국 문화축제 | 목록형이라 화면 구성 연습에 좋음 |
| 🥈 | 서울 따릉이 | 실시간성 체감이 큼 |

> KOBIS는 영화진흥위원회 자체 사이트에서 키를 받는다. 나머지는 data.go.kr에서 받는다.
> 수업에서는 **하나를 다 같이** 하고, 각자 원하는 데이터로 바꿔 보게 한다.

### 4.5 비밀키를 코드에 적으면 안 되는 이유

- 인증키는 **내 이름으로 발급된 열쇠**다. 남이 쓰면 내 한도가 소진되고 책임도 내게 온다.
- 코드에 그대로 적어 GitHub에 올리면 **누구나 볼 수 있다.** 자동으로 긁어가는 프로그램도 있다.
- 해결: **환경변수**로 분리한다. 코드에는 "키를 여기서 꺼내 쓴다"만 적고, 실제 값은 배포 설정에 넣는다.
- 실수로 올렸다면 **키를 폐기하고 새로 발급**받는다. 지우는 것만으로는 부족하다 — 이력에 남는다.
- 실물 예시: 이 강의 저장소가 계좌번호·토큰이 든 파일을 어떻게 제외했는지 3주차에 이어 다시 본다.
