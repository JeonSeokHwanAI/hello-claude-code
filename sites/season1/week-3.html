WEEK 03

스킬 제작을 위한 PRD 만들기 ✍️

2주차엔 PRD를 보고 Skill을 빌드했습니다. 이번 주는 거꾸로 — 본인이 만들고 싶은 도구의 PRD(설계 문서)를 직접 씁니다. 잘 쓴 PRD 한 장이면 Claude가 알아서 빌드합니다.

날짜2026-06-03 (수)
시간21:00~ (기본 2h)
난이도초급
선수 학습Week 2
제공 자료PRD 템플릿 · AI Blog Writer

학습 목표

  • 좋은 PRD의 구성요소(개요·기능 요구사항·연동 계약·부트스트랩)를 안다
  • 본인 아이디어를 기능 요구사항(F1, F2…)으로 쪼개 표로 정리한다
  • 입력 → 처리 → 출력과 파일 경로 계약을 명시할 수 있다
  • PRD 1장 초안을 완성해 Claude로 빌드 테스트까지 돌린다

왜 "PRD부터"인가

같은 요청, 다른 결과 — 설계서가 있으면 빌드가 재현 가능해집니다.

💬

"바로 만들어줘"

매번 결과가 다름 · 빠진 요구사항 뒤늦게 발견 · 다른 PC/프로젝트에서 재현 불가 · 대화가 길어질수록 산으로

📄

"PRD 보고 만들어줘"

요구사항이 표로 고정 · 누락 사전 점검 · PRD 한 장만 옮기면 어디서든 동일 빌드 · 기능 추가도 표에 한 줄

2주차 YouTube PRD가 그 증거입니다 — 2,500줄짜리 문서 한 장으로 두 스킬을 처음부터 빌드할 수 있었죠. 오늘은 그 PRD를 어떻게 쓰는지를 배웁니다.

PRD 구조 해부 (케이스 스터디)

YouTube PRD와 강사 도구 AI Blog Writer를 펼쳐, 잘 쓴 PRD에 꼭 들어가는 뼈대를 봅니다.

1. 개요        목적 · 사용 시나리오(S1, S2…) · 성공 기준(숫자로)
2. 기능 요구사항 F1, F2… 표 — "무엇을" 하는지 ID로 쪼갬
3. 연동 계약     자원 · 경로 · 쓰는 쪽 · 읽는 쪽 (도구 간 느슨한 결합)
4. 비기능       속도 · 보안(.env) · 호환성 · 로깅
5. 폴더/파일 배치 입력 → 작업 → 출력 트리
6. 부트스트랩    "이 PRD대로 빌드해줘" 한 줄 + Claude 빌드 절차
7. 레퍼런스 소스  (선택) 전체 코드 임베드 → 복사 없이 재현
AI Blog Writer 케이스 — 강사가 매일 쓰는 블로그 작성 도구를 "이미 만든 도구를 거꾸로 PRD로 옮겨 보기" 예제로 분해합니다. 본인 도구 설계의 출발점이 됩니다.

PRD 설계 4단계 사고

머릿속 아이디어를 빌드 가능한 문서로 옮기는 순서.

1

관찰 — 반복되는 일을 찾는다

"매주 똑같이 하는 손작업"이 후보. 무엇이 입력으로 들어오고 무엇이 결과로 나오는지부터 적는다.

2

쪼개기 — 기능 요구사항(F1, F2…)으로

큰 작업을 작은 기능 단위로 분해해 표로. 각 기능에 ID · 기능 · 설명을 붙인다.

3

입출력 · 계약 정의

입력 파일/경로, 출력 형식(.md·.html·.xlsx), 도구 간 주고받는 파일 경로(계약)를 명시한다.

4

부트스트랩 절차 작성

"이 PRD대로 빌드해줘"에 Claude가 따를 단계(폴더 생성 → 파일 작성 → 의존성 → 스모크 테스트)를 적는다.

커리큘럼 구성

3교시 × 25분 — "PRD 해부 → 라이브 작성 → 본인 PRD 작성"

1ST · 25min · 해부

PRD 구조 + 설계 4단계 사고

  • YouTube PRD / AI Blog Writer를 펼쳐 뼈대 분석
  • 좋은 PRD 5원칙 — 재현성·계약·숫자 성공기준
  • "바로 만들어줘" vs "PRD 보고" 비교
  • 관찰 → 쪼개기 → 계약 → 부트스트랩
2ND · 25min · 라이브

작은 도구 PRD 한 장 라이브 작성

  • 강사 라이브: "주간 업무 일지" 같은 작은 도구의 PRD를 즉석 작성
  • 기능 요구사항 표 → 입출력 → 부트스트랩까지
  • 완성한 PRD를 Claude에게 던져 그 자리에서 빌드
  • 빌드 실패 → PRD의 어디를 고쳐야 하나 디버깅
3RD · 25min · 본인 작업

본인 PRD 작성 + 코칭 + 시연

  • 2주차 과제로 메모해 온 "있으면 좋겠다" 기능을 PRD로
  • 강사 1:1 코칭 (15분) — 기능 쪼개기·계약 점검
  • 자원자 시연 2~3명 — PRD → 빌드 결과
  • 우수 PRD → 4주차 Agent 연동 재료

PRD 작성 체크리스트

  • 목적이 한 문장으로 적혔는가
  • 사용 시나리오(S1, S2…)가 구체적인가
  • 기능이 ID(F1, F2…)로 쪼개져 표로 정리됐는가
  • 입력 → 처리 → 출력 경로가 명시됐는가
  • 성공 기준이 숫자(시간·건수)로 적혔는가
  • "이 PRD대로 빌드해줘" 부트스트랩 절차가 있는가
  • 민감 정보(API 키 등)는 .env로 분리했는가
