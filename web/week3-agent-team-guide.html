Agent Team · Subagent 개념 가이드

Main Agent(메인 세션), Subagent(독립 작업자), Agent Team(팀 협업) — 세 가지가 무엇이 다르고, 언제·어떤 비용으로 쓰는지 정리했습니다.

조사일2026-04-07

1. Main Agent (메인 세션)

사용자와 직접 대화하는 주 세션. Claude Code를 실행(claude)하는 순간 자동으로 시작되며, 별도 설정이나 정의 파일 없이 생성됩니다. 즉, 사용자가 Claude Code와 대화하고 있는 그 세션 자체가 Main Agent입니다.

  • 전체 대화 이력, CLAUDE.md, 메모리를 보유
  • 작업을 판단하고 필요 시 subagent를 spawn하는 오케스트레이터 역할
  • 세션 종료까지 컨텍스트 유지 (누적됨)
  • Subagent를 생성할 수 있는 유일한 주체
  • .claude/agents/에 정의하는 것은 subagent이며, Main Agent의 정의 파일은 없음
PM (사용자) ↔ 지금 이 대화 (Main Agent)
                    │
                    ├→ doc-manager (subagent) spawn 가능
                    ├→ researcher (subagent) spawn 가능
                    ├→ community (subagent) spawn 가능
                    └→ ...

2. Subagent

메인 Agent가 Agent tool로 spawn하는 독립 작업자.

핵심 특성
  • 자체 컨텍스트 윈도우 — 메인 대화 이력을 상속받지 않음, spawn prompt만 수신
  • 프로젝트 컨텍스트 로드 — CLAUDE.md, MCP 서버, Skills는 자동 로드
  • 완료 시 컨텍스트 폐기 — 요약만 메인에 반환, 탐색 과정은 사라짐
  • 파일 변경은 유지 — 디스크에 쓴 파일은 남음
  • 다른 subagent 생성 불가 — 위임 체인 방지
완료 후 남는 것 vs 사라지는 것
남는다사라진다
요약 결과Main 컨텍스트에 반환-
생성/수정 파일디스크에 유지-
작업 과정-검색·파일 읽기·시행착오 전부
대화 이력-전부 폐기
같은 subagent를 다시 spawn하면 이전에 뭘 했는지 전혀 모릅니다. 매번 새 직원이 오는 것과 같습니다. → 쓰는 이유는 컨텍스트 효율성: 긴 탐색을 위임하면 메인 컨텍스트가 비대해지지 않고 요약만 돌아옵니다.
설정 옵션 — .claude/agents/{name}.md
---
name: "Research Agent"
description: "Researches topics and finds external resources"
model: "haiku"
tools:
  allow: [WebFetch, WebSearch, Glob, Grep]
  deny: [Bash, Write]
disabled: false
scope: project
---
옵션용도
modelsubagent 모델 override (sonnet, haiku 등)
tools.allow / deny도구 허용/차단
mcpServersMCP 서버 범위 지정
run_in_backgroundtrue = 비동기, false = 완료 대기
disabled삭제 없이 비활성화
scopeproject / user / plugin
isolation: "worktree"독립 git worktree에서 실행 (파일 충돌 방지)

3. Main Agent vs Subagent

Main AgentSubagent
컨텍스트대화 전체 누적매번 새로 시작 (spawn prompt만)
가시성사용자가 실시간 확인최종 요약만 반환

4. Agent Team

Claude Code의 실험적 기능(기본 비활성)으로, 여러 독립적인 Claude Code 세션이 팀으로 협업하는 구조입니다.

  • Team Lead: 팀을 생성하고 조율하는 메인 세션
  • Teammates: 각자 독립된 컨텍스트를 가진 별도 Claude Code 인스턴스
  • 공유 태스크 리스트: 팀원들이 자율적으로 claim하고 수행
  • 메시징 시스템: 팀원 간 직접 소통 가능
활성화 방법 (v2.1.32 이상)
// .claude/settings.json
{
  "env": { "CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS": "1" }
}

또는 CLI: claude --env CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1

제약 사항
제약대응
세션 resume 시 teammate 복원 안 됨새로 spawn
태스크 상태 지연 가능수동 확인
세션당 1팀, 중첩 불가기존 팀 정리 후 새 팀
Split pane은 tmux/iTerm2 필요Windows는 in-process 모드
토큰 비용 N배 (teammate 수)3명 시작 권장
Subagent vs Agent Team
SubagentAgent Team Teammate
통신메인에게만 반환팀원 간 직접 메시징
컨텍스트완료 시 폐기독립 세션으로 유지
조율메인이 순차 관리공유 태스크 + 자율 claim
비용낮음 (요약만 반환)높음 (독립 세션)
상호 통신불가 (메인 중개)직접 가능

5. 비용 비교: Subagent vs Agent Team

Subagent  = 직원 1명을 불러서 일 시키고 보고서 받기
Agent Team = 사무실 하나를 새로 차려서 팀 운영하기
시나리오별 토큰 사용량
리서치 1건토큰비유
Main이 직접~11,500사장님이 직접 조사
Subagent 위임~13,300 (+15%)직원 한 명 시켜 보고서
Agent Team~15,100 (+31%)팀 세팅 + 팀원이 조사
Subagent 1회 spawn 시 작업 시작 전 고정 비용 ≈ 1,800~3,500 토큰 (CLAUDE.md 로드 ~1,000 + MCP/도구 ~500 + spawn prompt ~300-500). Agent Team은 이 고정 비용이 teammate 수만큼 반복됩니다. ⚠️ Agent Team이 plan 모드로 돌면 단일 세션 대비 약 7배 토큰 소비.
비용 절감 전략 · 모델 배치
Main Agent (Lead)  → Opus    (판단·조율 품질 중요)
Subagent 일반      → Sonnet  (균형)
단순 작업          → Haiku   (저렴)
SubagentAgent Team
비용+15~30%+30~700%
장점메인 컨텍스트 보호, 저렴팀원 간 소통, 병렬 속도
쓸 때독립 작업 위임협업·토론이 필요할 때
돈 아끼려면 Subagent, 속도와 협업이 중요하면 Agent Team.

6. 실전 시나리오 — 정부과제 신청서 자료 준비

6개 Agent(community·researcher·doc-manager·simulator·reviewer·orchestrator)로 같은 일을 두 방식으로 처리한 비교.

Subagent 방식 (순차 중개)
PM → Main: "카톡 파일 분석해줘"
Main → community → 요약 반환 → Main
Main → researcher → 요약 반환 → Main
Main → doc-manager → 요약 반환 → Main
Main → reviewer → 요약 반환 → Main
Main → PM 최종 보고
문제: 모든 단계가 Main을 거쳐 순차. community가 끝나야 researcher 시작.
Agent Team 방식 (병렬 + 직접 소통)
community → doc-manager:  "필수서류 5종, 마감 2026-04-25"
community → researcher:   "주관기관 KEIT, 예산 확인 필요"
researcher → doc-manager: "유사과제 3건, 차별화 전략 반영 권고"
doc-manager → simulator:  "기술개발계획서에 시뮬레이션 스펙 필요"
simulator → doc-manager:  "ROS2 Humble + Gazebo 스펙 정리 완료"
Subagent였다면 위 5건 모두 Main을 거쳐 5번의 spawn-반환 사이클.
Subagent (현재)Agent Team
소요 시간순차 5단계병렬 → 빠름
Main 컨텍스트5개 요약 누적Lead는 최종 보고만
중간 소통Main 거쳐 5회 중개teammate 간 직접 5회
비용기본~3-4배
PM 개입매 단계 확인 가능[확인 필요]만 보고
2026-04-07 시뮬레이션(각 역할을 subagent로 재현): teammate 간 소통 5건을 처리할 때 Subagent는 Main 개입 5회·요약 4개 누적, Agent Team(이론)은 Main 개입 0회·최종 보고만. 원문에는 settings.json/CLAUDE.md 전환 내역과 전체 프롬프트가 추가로 정리되어 있습니다.
